# ⚠️ 制約と適用範囲

現在の SpriteStudio Player for Ren'Py における制限事項・未実装の機能の一覧です。（サポートしている機能の一覧は利用ガイドを参照してください。）

このページは **この Player 固有** の内容を扱います。共通ランタイム由来で、すべての公式 Player に当てはまる制約 — `independent=true` パーツの逆再生・シーク、シーク時に通過フレームのイベントが発火しないこと、オーディオの逆再生非対応、`.ssab` の入力検証を行わないこと — は、ポータルの **[共通の制限事項](https://cri-middleware.github.io/SpriteStudio-Docs/ja/sdk/limitations/)** に集約されています。

## 未実装 (Not Yet Implemented)

> [!WARNING]
> - **Text / NineSlice パーツ** — 描画されません（空表示になります）。

## 部分的にサポート (Partially Supported)

> [!WARNING]
> - **ブレンドモード** — ブレンドは Ren'Py の `config.gl_blend_func` を経由するため、GL に相当がないモード（Division, Overlay）は Mix にフォールバックします。
> - **テクスチャ上限を超えるアトラス** — `config.max_texture_size`（既定 4096x4096。GPU の上限を超えることはありません）より大きいテクスチャは、タイルに分割して読み込まれ、メッシュからはサンプリングできません。そのアトラスを使うパーツは、より単純な transform 経路で描画されます（形は正しく出ますが、メッシュ変形と UV 変形は反映されません）。同じアトラスを使う Effect のパーティクルは描画されません。いずれの場合も `log.txt` に該当アトラス名が出力されます。パックをより小さいアトラスで書き出し直すか、`options.rpy` で `config.max_texture_size` を引き上げてください（引き上げると Ren'Py が確保するフレームバッファも大きくなります: 4096 から 8192 で 64MB から 256MB）。
> - **Mesh / Instance パーツのパーツ全体カラー** — `parts_color` は Normal / Shape パーツでは各頂点に適用されますが、Mesh パーツ全体への色味付けは現状アルファのみの近似です。
> - **Effect パーティクルへのマスク** — マスク / クリッピングが効くのは Normal・Mesh・Shape パーツです。Effect パーツが放出するパーティクルは、エディタ上でクリップされる場合でもクリップされずに描画されます。
> - **1 つのアニメーションで同時に使えるマスクは 96 個まで** — マスクパーツと、クリッピングのマスクを書くパーツの両方を数え、Instance パーツで再生するアニメーションの分も含みます。インスタンスの中のマスクは、そのインスタンスを置いた回数だけ数えます。非表示のマスクや、マスク値が 0 のマスクは数えません。96 個を超えた分は、後から描かれるものから無視され、`log.txt` にその旨が出力されます。24 個までは元の解像度で描かれ、それを超えるとメモリを増やす代わりにマスクの縁が粗くなります。
> - **Instance パーツ内部へのパーツオーバーライド** — カラー / セル / 表示のオーバーライドが届くのは、呼び出したアニメーション自身のパーツまでです。Instance パーツの内部のパーツ（入れ子の子アニメーションは別プレイヤーとして動作します）には届きません。Instance パーツ自体を強制的に隠せば、その中身も描画されなくなります。
> - **アニメーションのブレンド**（[クロスフェードと重ね合わせ](usage.md#mixing-animations)）— トラックのスタックはセーブされません。セーブをロードすると、プレイヤーはトラック 0 のアニメーションのセーブ時のフレームから戻り、他のトラックや進行中のフェードはありません。画像の属性によるアニメーションの切り替え（`show ringo walk`）はクロスフェードせずに切り替わります。クロスフェードさせるには、変数に持ったプレイヤーで `ss_crossfade()` を呼んでください。トラック 0 のクロスフェードでは、両方のアニメーションが同じフレームにキーを持つ Instance / Effect パーツが、出ていく側の設定のまま動き続けることがあります。
> - **パーツトラッキング（パーツへの追従）** — 追従させた子は常にスプライト**全体の手前**に描画され、パーツ間に差し込むことはできません。また反転（マイナススケール）したパーツでも子は反転しません（パーツの拡縮は絶対値として得られるためです）。位置と角度は正確ですが、左右反転しているだけのパーツは子には 180 度の回転として届きます（詳細は[使い方ガイド](usage.md#反転鏡像したパーツ)の「反転（鏡像）したパーツ」）。追従先に指定できるのは、そのプレイヤー自身が再生しているパックのパーツまでで、Instance パーツ内部のパーツは指定できません。
> - **ボタン**（[`SSButton`](buttons.md)）— Ren'Py のボタンにはマウスを押し続けている間の状態が無いので、`SSButton` にもありません。`parts` に指定できるのは、そのプレイヤー自身が再生しているパックのパーツまでで、Instance パーツ内部のパーツは指定できません。

## オーディオ再生 (Audio Playback)

> [!NOTE]
> 通常の使い方（順再生で、スプライトを普通に表示 / 非表示する）ではそのまま鳴ります（`sfx` ミキサー上で再生されるため、プレイヤーの音量・ミュート設定も効きます）。注意が要るのは次のエッジケースだけです。
>
> - **逆再生の音は鳴らない** — アニメーションが逆方向（逆再生 / ピンポンの復路）に進むとき、その音はスキップされます（音声は逆再生できないため）。負の再生速度はこれに該当しません。速度は倍率であり、負値は再生ヘッドの向きを変えるのではなく停止させます（`0` も同様）。
> - **シークで音はスクラブされない** — 音は再生中に再生ヘッドがそのフレームを通過した瞬間のみ発火します。フレームのジャンプ（`ss_set_frame_no`）ではスクラブも、飛ばした音の再発火もしません。
> - **音は発火させた再生より長く生き残る** — `ss_pause()` / `ss_stop()` が終わらせるのは *アニメーション* であって音ではありません。SpriteStudio に無限ループの音はなく（`loop_num` は再生回数）、すべての音はいつか自然に終わります。アニメーションの尺より長く鳴る音があるなら、それはアニメーションデータ側の問題です。音を止めたい場合は `ss_stop_audio()` を呼んでください。
> - **手動管理のプレイヤーの停止** — `hide` / `scene` なら音は即座に止まります。`SSPlayer` を変数に保持して自分で差し替える場合は、`ss_stop_audio()` を呼ぶと即停止します（呼ばなくても画面から外れて約 0.25 秒以内に自動停止）。
> - **サウンドファイルを `.ssab` と同梱** — テクスチャ同様、`.ssab` からの相対で解決します。存在しないファイルはスキップされます。

## パフォーマンス・プラットフォーム (Performance & Platform)

> [!NOTE]
> **パフォーマンスについて** — メッシュの頂点数が極端に多いアニメーションや、大量のパーティクルが多数重なるエフェクトでは、フレームレートに影響が出る可能性があります。

> [!WARNING]
> **プラットフォーム** — すべてのターゲットに対応しています: デスクトップ (Windows / macOS / Linux)、Android、iOS、Web。各プラットフォームへのエクスポート手順は[エクスポートガイド](export.md)を参照してください。プラットフォーム固有の注意点は以下です:
>
> - **Android** はアプリ自身のライブラリフォルダからしかネイティブコードを読み込まないため、最初の Android ビルドの前に、このプレイヤーの `.so` を RAPT へ一度だけ手でコピーします（[Android 向けエクスポート](export.md#android-向けエクスポート)）。
> - **iOS** は macOS + Xcode が必要で、このプレイヤーのライブラリをアプリターゲットへ一度だけ手で埋め込みます（[iOS 向けエクスポート](export.md#ios-向けエクスポート)）。
> - **Web** は **WebAssembly SIMD** に対応したブラウザ（Chrome / Edge 91 以降、Firefox 89 以降、Safari 16.4 以降）が必要です。このプレイヤーの WebAssembly 版は SIMD 命令でビルドされており、**SIMD 非対応のブラウザでは動作しません**。配信先のブラウザ要件として SIMD 対応を前提としてください。
